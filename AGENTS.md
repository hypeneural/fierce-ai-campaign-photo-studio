# AGENTS.md — Campaign Photo Studio

This file is the source of truth for coding agents working in this repository.

## Mission

Build a fast, privacy-first photo-frame studio that can serve multiple campaign identities and formats from one rendering engine. The public user flow should remain short: choose identity/template → choose format → select photo → adjust crop/zoom → export/share.

## Non-negotiable architecture

1. **No candidate-specific rendering branches.** Candidate identity belongs in template/campaign data.
2. **Public photos are local-first.** Do not upload or persist user photos unless a future requirement is explicitly documented and approved in an ADR.
3. **Final output is rendered at target resolution.** Never export the preview DOM as the canonical result.
4. **Use Canvas `toBlob()`, not `toDataURL()`, for final export.**
5. **User uploads:** allow JPEG, PNG and WebP only. Do not accept user-supplied SVG.
6. **Trusted internal assets:** SVG/PNG/WebP are allowed for repository-controlled templates.
7. **Preserve aspect ratio.** Never stretch a user photo into `photoArea`; crop/cover instead.
8. **Separate preview state from rendering state.** Preview dimensions may change; target dimensions may not.
9. **Normalized intent over screen pixels.** Persist focal points/transforms in normalized coordinates if state must move across formats.
10. **No persuasive political copy is generated by the engine.** Template artwork/copy is an approved content input; the codebase only renders it.

## Image-engine rules

- Keep pure math in `src/image-engine/` where possible.
- Revoke every `URL.createObjectURL()` when it is no longer needed.
- Treat EXIF/orientation, huge dimensions and decompression cost as input concerns.
- Downscale oversized originals before expensive repeated rendering.
- Set explicit max bytes and max decoded megapixels before production release.
- A user transform must yield deterministic output for the same template and source image.
- Multi-format export should reuse the decoded source image instead of decoding once per format.

## Template rules

- Every template has explicit `width`, `height`, `photoArea`, `layers` and export policy.
- Coordinates are normalized (`0..1`) in stored config unless a compelling reason is documented.
- Templates are versionable. Published templates should not be destructively changed without a migration/version bump.
- Placeholder templates may use internal SVG. Production artwork should be reviewed separately.

## Privacy and analytics

- Analytics events should record aggregate product behavior (view, upload-start, export, share), not the photo.
- Do not join an identifiable contact record to a political-template choice by default.
- Any future contact/CRM flow must be isolated from the local image editor and reviewed for legal/privacy requirements.

## Tests required for engine changes

At minimum cover:
- cover/crop math for portrait, landscape and square photos;
- photoArea mapping for 1:1 and 9:16 templates;
- no-stretch invariant;
- MIME allowlist;
- template schema validation;
- export dimensions.

## Pull request checklist

- `npm run typecheck`
- `npm run lint`
- `npm test`
- `npm run build`
- No new photo-upload endpoint was introduced accidentally.
- No candidate-specific branch was added to image-engine code.
- Any schema change is reflected in `docs/TEMPLATE-SPEC.md`.
